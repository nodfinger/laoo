## กติกาการแสดง Action ต่อรายการ

ทุกแถวต้องอ่าน `ScreenType` จาก `TDADMainMenu` ด้วย `MenuCode` ของแถวนั้นก่อนสร้าง Checkbox ห้ามกำหนดชุด Action จากหน้าจอแบบตายตัว

| ScreenType | แสดง Action |
|---:|---|
| `1` CRUD | แสดง `แสดง`, `เพิ่ม`, `แก้ไข`, `ลบ` |
| `2` UpdateOnly | แสดง `แสดง`, `แก้ไข` เท่านั้น |
| `3` ShowOnly | แสดง `แสดง` เท่านั้น |

## Behavior

- เปิดหน้าแล้วเลือก `กลุ่มสิทธิ์` ก่อนโหลด Matrix; ข้อมูลสิทธิ์ต้องเป็นของ Scope ปัจจุบันเท่านั้น
- แถวเมนูอ่านจาก Navigation/`TDADMainMenu` และจับคู่ด้วย `MenuCode` ไม่ใช้ชื่อเมนูเป็นตัวตน
- `ScreenType=1`: Checkbox ทั้ง 4 รายการกดได้
- `ScreenType=2`: Checkbox `แสดง` และ `แก้ไข` กดได้; `เพิ่ม`/`ลบ` ไม่แสดงหรือ disabled ตามมาตรฐานที่อนุมัติ
- `ScreenType=3`: แสดงเฉพาะ Checkbox `แสดง`; Action อื่นไม่แสดง
- ถ้าไม่มี `แสดง` จะไม่ให้เลือก Action อื่น และ Backend ต้องตรวจซ้ำ
- ไม่มีคอลัมน์ `สถานะ` ใน Matrix นี้; สถานะการใช้งานของพนักงาน/การผูกกลุ่มจัดการที่หน้าผู้ใช้งาน
- ปุ่ม `บันทึก` แสดง Success Popup ด้านบนตาม `TimeAlert`; Error/ลบใช้ Popup แดง และข้อความเป็นภาษาไทย
- Pagination อยู่ล่างชิดซ้าย ใช้ปุ่มวงกลม `ก่อนหน้า / เลขหน้า / ถัดไป` และจำนวนรายการจากข้อมูลจริง
- Header และ Checkbox ใช้สี/Font จาก User Style และ Theme กลาง

## การกำหนดกลุ่มสิทธิ์ให้พนักงาน

ดำเนินการที่หน้า `พนักงาน` หรือ `ผู้ใช้งาน` ไม่ใช่หน้า `สิทธิ์เมนู`:

```text
พนักงาน > แก้ไข
┌──────────────────────────────────────────────────────────────┐
│ พนักงาน > แก้ไข                                             │
│ ชื่อพนักงาน        [____________________________]            │
│ กลุ่มสิทธิ์         [ ผู้ปฏิบัติงาน                  ▼ ]     │
│ วันที่เริ่มใช้      [ วัน/เวลาเริ่มต้น              ]        │
│ วันที่สิ้นสุด       [ ไม่กำหนด                       ]        │
│                                      [ยกเลิก] [บันทึก]       │
└──────────────────────────────────────────────────────────────┘
```

- พนักงานหนึ่งคนเลือกกลุ่มสิทธิ์ตาม Scope ของ Customer หรือ Partner
- ตอน Login/ตรวจสิทธิ์ ระบบอ่านกลุ่มสิทธิ์ที่มีผล ณ วันเวลาปัจจุบัน
- ถ้าไม่ใช้ช่วงเวลา ให้เก็บเฉพาะ `RoleGroupID` และถือว่าใช้ตั้งแต่บันทึกจนกว่าจะเปลี่ยนกลุ่ม
- Backend ต้องตรวจ Scope, วันที่มีผล และ Permission ซ้ำทุกครั้ง

จุดที่ต้องยืนยันก่อนเริ่ม Code: พนักงานหนึ่งคนให้มีได้กี่กลุ่มสิทธิ์พร้อมกัน และต้องการวันที่เริ่ม/สิ้นสุดหรือใช้กลุ่มปัจจุบันเพียงกลุ่มเดียว
