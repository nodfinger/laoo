# ต้นแบบค้นคำตอบจากคู่มือระบบห้องประชุม

## เป้าหมาย

ให้ผู้ใช้ถามวิธีใช้งานระบบห้องประชุมผ่าน Chat AI ภายในองค์กร โดยค้นเนื้อหาจากคู่มือของบริษัทที่ได้รับอนุญาต แล้วแสดงคำตอบพร้อมชื่อเอกสารและเลขหน้าต้นทาง การค้นคู่มือเป็นการอ่านข้อมูล ไม่จองห้องหรือเปลี่ยนข้อมูลในระบบ

## คู่มือเริ่มต้น

- ไฟล์ต้นฉบับ: `C:\Users\IT_Chokchai\Desktop\Royalplus\รวมคู่มือ\ระบบจองห้องประชุม\เนื้อหาคู่มือ.pdf`
- เก็บต้นฉบับไว้ตามเดิม ระหว่างทดลองไม่ส่งไฟล์หรือข้อความในคู่มือออกอินเทอร์เน็ต
- ต้องตรวจความถูกต้องของข้อความภาษาไทยที่สกัดออกมาเทียบกับหน้าต้นฉบับ โดยเฉพาะข้อความในภาพ ก่อนนำมาใช้ตอบจริง

## แนวทางดำเนินงาน

1. ตรวจสิทธิ์การเข้าถึงคู่มือ กำหนดบริษัทเจ้าของและผู้ที่อ่านได้ รวมทั้งตรวจแพ็กเกจ AI และสิทธิ์ระบบห้องประชุมจาก Backend
2. สกัดข้อความแยกหน้าและตรวจคุณภาพ หากบางหน้าเป็นภาพให้ใช้ OCR ภายในองค์กรและตรวจผลกับต้นฉบับ
3. แบ่งเนื้อหาเป็นช่วงสั้นตามหัวข้อ โดยเก็บชื่อไฟล์ รุ่นเอกสาร เลขหน้า และข้อมูลบริษัทกำกับทุกช่วง
4. ค้นเฉพาะช่วงที่ผู้ใช้มีสิทธิ์ แล้วส่งข้อความที่ค้นพบให้โมเดลภายในสรุปคำตอบพร้อมแหล่งอ้างอิง หากไม่พบให้แจ้งว่าไม่พบ ไม่เดาคำตอบ
5. ทดสอบคำถามจากคู่มือและคำถามที่ไม่มีคำตอบ ตรวจเลขหน้า ภาษาไทย และการแยกบริษัท ก่อนเปิดให้ใช้งานจริง

เริ่มด้วยไฟล์เดียวได้ และไม่จำเป็นต้องฝึกโมเดลใหม่ การเพิ่มคู่มือหรือแก้ไขรุ่นในอนาคตต้องสร้างดัชนีใหม่และตรวจสิทธิ์ก่อนเผยแพร่

## สถานะปัจจุบัน

- พบไฟล์คู่มือต้นฉบับและสกัดข้อความแยกครบ 6 หน้าแล้ว ผลชั่วคราวเก็บใน `artifacts/meeting-manual/pdf-text.json` ซึ่ง Git ไม่ติดตาม
- โครงสร้าง Agent ปัจจุบันยังไม่ได้เชื่อมการค้นคู่มือเข้ากับ Chat
- ติดตั้ง `pypdf 7.0.0` และ `PyMuPDF 1.26.7` ไว้ภายใน `tools/local-python/` โดย Git ไม่ติดตาม ใช้ `tools/scripts/inspect-pdf-text.py` เพื่อสกัดข้อความพร้อมเลขหน้าแบบออฟไลน์
- เครื่องมือทั้งสองสกัดข้อความได้ แต่พบตัวอักษรและวรรณยุกต์ภาษาไทยเพี้ยนในไฟล์ต้นฉบับ จึงยังไม่ควรใช้ข้อความที่สกัดเป็นฐานตอบ ต้องตรวจเทียบต้นฉบับและทดลอง OCR ภาษาไทยภายในเครื่องก่อน
- ยังไม่ได้สร้างดัชนีหรือบันทึกข้อมูลลง SQL Server
- ต้องพัฒนาและทดสอบ Backend การค้นคู่มือ สิทธิ์ แหล่งอ้างอิง และการเชื่อม Chat ก่อนจึงจะใช้งานจริงได้
