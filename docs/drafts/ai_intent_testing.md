# แบบร่างหน้าทดลองคำถาม AI

สถานะ: ผู้ใช้กำหนด MenuCode 64001 และ ScreenType 3 แล้ว ตรวจพบว่ารหัสว่างในฐานข้อมูลขณะตรวจสอบ เตรียมการลงทะเบียนผ่าน migration และต้องตรวจซ้ำก่อนใช้งานจริง

## วัตถุประสงค์

ให้ผู้มีสิทธิ์ทดลองการจำแนกคำถามในบริษัทของตน โดยใช้โมเดลภายในและตัวอย่างที่บริษัทตั้งไว้เช่นเดียวกับ Chat แล้วเปรียบเทียบกับคำตอบที่คาดหวัง การทดลองไม่เรียก Action จริง ไม่สร้างใบงาน ไม่ส่งอีเมล ไม่เก็บข้อความหรือผลทดสอบถาวร และไม่ฝึกโมเดล

## ส่วนหน้าจอ

- Caption Card ตามมาตรฐาน มีไอคอน ชื่อเมนูจากข้อมูลเมนู และดาวเมนูลัดตามสิทธิ์
- Card ทดลอง มี Combo ความสามารถที่ผู้ใช้มีสิทธิ์ใช้งาน ช่องข้อความคำถาม และ Combo ประเภทคำตอบที่คาดหวัง พร้อมปุ่มทดลองและล้าง ใช้สีและขนาดตาม User Style
- Card ผลลัพธ์ แสดงประเภทที่ระบบจำแนก คำตอบที่คาดหวัง และผลตรง/ไม่ตรง อธิบายว่าโมเดลอาจให้ผลต่างกัน เมื่อไม่เข้าใจหรือบริการไม่พร้อมให้แจ้งสาเหตุและวิธีลองใหม่
- แสดงเฉพาะข้อมูลที่อนุญาตตาม Company, แพ็กเกจ AI, สิทธิ์เมนูทดลอง และสิทธิ์ความสามารถต้นทาง การทดสอบไม่ขยายสิทธิ์ไปยัง Project อื่น

## การเชื่อมต่อและเงื่อนไข

ต้องใช้ logic จำแนกเดียวกับ `/api/assistant/message` และตรวจสิทธิ์จาก session จริง ห้ามนำ CompanyID, SQL หรือ URL จากข้อความผู้ใช้มาใช้ดำเนินการ ไม่ส่งข้อมูลไป endpoint ภายนอก ปุ่มทดลองไม่ส่งข้อมูลไป API สร้าง แก้ไข ลบ หรือส่งอีเมล

ตรวจ MenuCode และ ScreenType จริงก่อนตัดสินใจเกี่ยวกับสิทธิ์ VIEW และการลงทะเบียน Route ไม่ใช้รหัสสมมติในฐานข้อมูล ชื่อเมนูอ่านจากข้อมูลเมนูจริงตามมาตรฐาน

## เกณฑ์ทดสอบ

- เปรียบเทียบผลกับ Chat ภายใต้บริษัทและสิทธิ์เดียวกัน รวมกรณีไม่ตรงและไม่เข้าใจ
- บริษัทปิดแพ็กเกจหรือหมดอายุ ผู้ไม่มีสิทธิ์ และผู้ใช้ต่างบริษัทต้องไม่ได้รับข้อมูลหรือเรียก API
- ตรวจว่าไม่มีการบันทึกข้อความ ทดสอบด้วยข้อมูลสมมติเท่านั้น และไม่มีการสร้างเอกสารหรือส่งอีเมล
- ตรวจจอกว้าง จอเล็ก สีตาม User Style สถานะโหลด และกรณีโมเดลภายในไม่พร้อม
