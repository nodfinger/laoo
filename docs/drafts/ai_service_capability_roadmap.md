# ความสามารถ AI สำหรับงานแจ้งซ่อม

เอกสารเตรียมการพัฒนา โดยความสามารถด้านล่างยังไม่ได้เปิดใช้งานผ่าน AI

| ความสามารถ | ตัวอย่างคำถาม | API ปัจจุบัน | เงื่อนไขที่ต้องตรวจ |
|---|---|---|---|
| ดูรายละเอียดใบแจ้งซ่อม | ใบแจ้งซ่อม SR… เป็นเรื่องอะไร | GET /api/service/requests/{id} | บริษัท เมนู สิทธิ์ดู และขอบเขตข้อมูล |
| ดูงานรอรับ | งานซ่อมรอรับมีอะไรบ้าง | GET /api/service/requests?menuCode=17001 | สิทธิ์เมนู 17001 และบริษัท |
| รับงาน | รับงาน SR… ให้ช่างสมชาย | POST /api/service/requests/{id}/receive | สิทธิ์ สถานะ NEW ช่างในบริษัท แบบประเมินตามการตั้งค่า และยืนยันก่อนบันทึก |
| เริ่มงาน | เริ่มซ่อมใบงาน SR… | POST /api/service/requests/{id}/start | สิทธิ์ สถานะ RECEIVED และยืนยันก่อนบันทึก |
| ปิดงาน | ปิดงาน SR… เปลี่ยนสายไฟแล้ว | POST /api/service/requests/{id}/complete | สิทธิ์ สถานะ IN_PROGRESS ผลการซ่อม อะไหล่และสต๊อก และยืนยันก่อนบันทึก |

## แนวทางพัฒนา

- เพิ่มความสามารถทีละรายการในทะเบียน Backend และ Service Agent พร้อมรายการตัวอย่างที่แยกตามบริษัท เริ่มต้นปิดไว้
- ขยายตัวจำแนกให้รองรับรหัสความสามารถใหม่ โดยโมเดลเลือกได้เฉพาะรหัสที่ Backend อนุญาตเท่านั้น
- ค้นหาและตรวจสิทธิ์ใบงานจากข้อมูลผู้ใช้จริง ไม่รับ CompanyID หรือ URL จากข้อความ AI
- สำหรับรายการที่เปลี่ยนข้อมูล ให้แสดงสรุปและขอยืนยัน ตรวจสิทธิ์และสถานะซ้ำที่ Backend ก่อนเรียกขั้นตอนเดิม และป้องกันการส่งซ้ำ
- การปิดงานต้องไม่ละเลยรายการอะไหล่ การตัดสต๊อก หรือการตรวจ Serial ตามขั้นตอนเดิม หากข้อมูลไม่ครบให้ถามเพิ่มหรือส่งไปหน้าจอปกติ
- ทดสอบด้วยข้อมูลจำลองหรือฐานทดสอบ แยกบริษัทและสิทธิ์ รวมถึงยกเลิก ยืนยันซ้ำ สถานะเปลี่ยน และสต๊อกไม่เพียงพอ ก่อนติดตั้ง migration หรือเปิดใช้งานจริง
