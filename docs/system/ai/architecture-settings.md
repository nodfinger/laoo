# สถาปัตยกรรมและการตั้งค่า AI

## ข้อกำหนดปัจจุบัน

# โครงสร้าง Agent ภายในองค์กร

## ส่วนกลางและ Agent เฉพาะระบบ

`AssistantIntentClassifier` ตรวจตัวอย่างคำถามที่บริษัทเปิดใช้และผู้ใช้มีสิทธิ์ก่อนเรียกโมเดลภายใน ส่วน `AssistantAgentRouter` เป็นตัวกลางจับคู่รหัสความสามารถกับ Agent ที่ขึ้นทะเบียน โดยรับเฉพาะความสามารถที่ผ่านการตรวจสิทธิ์แล้ว ตัวกลางไม่สร้าง SQL ไม่เลือก URL และไม่เรียกคำสั่งที่เปลี่ยนข้อมูลเอง

`AssistantAgentRegistry` เป็นทะเบียน Agent ที่พัฒนาใน Backend โดยนิยามแยกตามระบบใน `Services/Assistant/Agents`:

- `ServiceAssistantAgent`: ความสามารถแจ้งซ่อม ติดตามงานของตนเอง และสรุปต้นทุนอะไหล่ที่ระบบรองรับอยู่
- `TravelAssistantAgent`: สรุปค่าเบิกเดินทางของตนเองหรือหน่วยงานตามสิทธิ์ดูข้อมูลในเมนู 66001; API อ่านอย่างเดียวและคืนยอดรวม
- `StockAssistantAgent`: โค้ดปัจจุบันลงทะเบียน `stock.serial_lookup`; การเปิดใช้จริงขึ้นอยู่กับบริษัทและสิทธิ์

การตั้งชื่อและข้อความแนะนำตัวเป็นค่าการแสดงผลแยกบริษัท ไม่ทำให้ได้รับสิทธิ์เพิ่ม การใช้ความสามารถยังต้องผ่านการตรวจ AI Chat แพ็กเกจ เมนู Action และขอบเขตข้อมูลจาก Backend ทุกครั้ง

## การเพิ่ม Agent หรือความสามารถ

1. ระบุงาน ขอบเขตข้อมูล Project, MenuCode และ Action ที่จำเป็น รวมถึงสถานการณ์ที่ต้องให้ผู้ใช้ยืนยัน
2. พัฒนาตัวทำงานที่เรียกขั้นตอนของระบบเดิมผ่าน Backend และขึ้นทะเบียนรหัสความสามารถใน `AssistantCapabilities` และ Agent ที่เกี่ยวข้อง ไม่รับ SQL, URL, CompanyID หรือสิทธิ์จากข้อความโมเดล
3. เพิ่ม metadata และค่าเริ่มต้นรายบริษัทผ่าน migration โดยให้ความสามารถใหม่ปิดไว้ก่อน และไม่เขียนทับการตั้งค่าที่มีอยู่
4. ทดสอบสิทธิ์ต่างบริษัท แพ็กเกจปิด ขอบเขตข้อมูล ข้อมูลไม่ครบ และการส่งซ้ำ ก่อนเปิดใช้งาน

## สิ่งที่ยังไม่พร้อม

ตัวกลางรองรับการจับคู่รายการความสามารถหลายรายการในโค้ด แต่การแยกคำถามหลาย Agent การเรียกทั้งสองระบบและรวมผลใน Chat ยังไม่เสร็จ รวมถึงการปิดงานผ่าน AI และการค้นคู่มือ migration การตั้งค่า Agent และเมนู 64003 ติดตั้งในฐานข้อมูลจริงแล้ว โดยไม่เพิ่มข้อมูลการตั้งค่ารายบริษัทหรือสิทธิ์ให้กลุ่มใดโดยอัตโนมัติ


# ตั้งค่า AI Chat รายบริษัท

- Partner Admin เปิดหรือปิด `AI Chat` ในหน้ากำหนดแพ็กเกจของลูกค้าแต่ละบริษัท ระบบคงสถานะเปิดสำหรับบริษัทที่มีอยู่เดิมตาม migration
- ผู้มีสิทธิ์แก้ไขหน้ากำหนดค่าระบบของบริษัทตั้งชื่อ คำเรียก รูปแบบคำทักทาย ช่วงเวลา และรูป AI ได้ในการ์ด `ตั้งค่า AI Chat` โดยใช้ปุ่มบันทึกด้านบนร่วมกับข้อมูลบริษัท รูปที่เลือกจะรอบันทึกพร้อมการตั้งค่า หากบันทึกบางส่วนไม่สำเร็จระบบจะแจ้งให้ทราบ
- ช่วงเวลาคิดตามเวลาท้องถิ่นของเครื่องผู้ใช้ จุดเริ่มรวมอยู่ในช่วง จุดสิ้นสุดไม่รวมอยู่ในช่วง รองรับช่วงข้ามเที่ยงคืนและห้ามช่วงเวลาทับซ้อน ถ้าอยู่นอกช่วงที่กำหนดจะไม่แสดงข้อความทักทายตามเวลา รูปแบบที่ 2 เรียกเพียง `คุณ`
- ช่วงค่ำเพิ่มเป็นตัวเลือกที่ยังไม่กำหนดโดยเริ่มต้น ต้องระบุเวลาเริ่มและสิ้นสุดทั้งคู่เมื่อต้องการใช้งาน และต้องไม่ทับซ้อนช่วงอื่น
- รูป AI รองรับ JPG, PNG และ WEBP ไม่เกิน 3 MiB (3 × 1024 × 1024 bytes) จัดเก็บบน API Server ใน `laoo_api/uploads/ai-chat/<CompanyID>` นอก web root ต้องสำรองโฟลเดอร์นี้คู่กับฐานข้อมูล รูปส่งผ่าน API ที่ตรวจบริษัทและสถานะเปิดใช้งาน
- การเปลี่ยนสถานะจาก Partner มีผลต่อการเรียก AI ที่ Backend ทันที ส่วนปุ่ม Chat ใน Session ที่เปิดค้างอยู่ตรวจสถานะซ้ำทุก 30 วินาที
- การเปิด AI Chat ไม่ได้ให้สิทธิ์เมนูหรือเปิดแพ็กเกจของ Project อื่น ความสามารถแต่ละอย่างยังตรวจสิทธิ์ของผู้ใช้และบริษัทก่อนใช้งาน


## พฤติกรรมที่พบในโค้ด

รูป AI Chat และ Agent ตรวจไม่เกิน 3 MiB ใน Frontend และ Backend; ข้อความ UI แสดง 3 MB ดูรายงานผลกระทบ
