### Flow งานซ่อม

```text
ทะเบียน/อุปกรณ์/สถานที่
  → แจ้งซ่อม หรือสแกน QR
  → NEW
  → รับเรื่องและมอบหมายช่าง
  → RECEIVED
  → เริ่มดำเนินการ
  → IN_PROGRESS
  → บันทึกผลและปิดงาน
  → COMPLETED

NEW / RECEIVED / IN_PROGRESS
  → ยกเลิกตามสิทธิ์
  → CANCELLED
```

## 3. งานที่ทำแล้ว แต่ต้องทดสอบรับมอบ

- 🟡 Permission, Company Scope และการเปิดใช้งาน Project `LAOO_SERVICE`
- 🟡 รูปภาพแนบ: หลายไฟล์, ลดขนาด, ปฏิเสธเฉพาะไฟล์ที่ไม่ผ่าน และห้ามแก้ไขหลังปิด/ยกเลิก
- 🟡 QR จากมือถือ → `/portal/request?qr=...` → อุปกรณ์และสถานที่ถูกเติมจาก Backend
- 🟡 Snapshot ผู้แจ้ง, โทรศัพท์, สถานที่, อุปกรณ์ และช่างไม่เปลี่ยนตามทะเบียนภายหลัง
- 🟡 ลำดับสถานะและ Conflict เมื่อผู้ใช้อื่นเริ่ม/ปิดงานก่อน
- 🟡 Responsive, ภาษาไทย และ Overflow บน Desktop/Mobile ทุกเมนู Service
- 🟡 สิทธิ์ `VIEW`, `CREATE`, `EDIT`, `DELETE`/Action ถูกตรวจซ้ำที่ Backend

## 5. Scope Dashboard ภาพรวมงานบริการ

Dashboard `19001` จะใช้ข้อมูลใบแจ้งซ่อมและ Snapshot เดิม โดยมีขอบเขตเริ่มต้นดังนี้:

- KPI ตามสถานะ `NEW`, `RECEIVED`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED` และช่วงเวลา
- มุมมอง/ตัวกรองตาม Company Business Type:
  - หอพัก/สำนักงานเช่า: อาคาร, ชั้น, ห้อง
  - หมู่บ้าน: ซอย/แยก, บ้านเลขที่
  - บริษัท/ศูนย์บริการ: สถานที่หรือข้อมูลผู้ใช้บริการตาม Flow
- มุมมองงานค้าง, ช่างผู้รับผิดชอบ และระยะเวลาดำเนินการ
- กด KPI หรือกราฟเพื่อเปิดรายการใบงานที่ถูก Filter แล้ว
- รองรับ Desktop และ Mobile โดยไม่เกิด Overflow

## 6. หลักควบคุมร่วม

- ทุกข้อมูลต้องถูกกรองด้วย Company Scope และตรวจการเปิดใช้ `LAOO_SERVICE`
- UI ซ่อน Action ตามสิทธิ์ แต่ Backend ตรวจซ้ำทุก Action
- เอกสารงานซ่อมเก็บ Snapshot เพื่อรักษาประวัติเดิม
- รายการอุปกรณ์สำหรับงาน Service ต้องมี Usage `EQUIPMENT`
- QR ใช้ได้เฉพาะ Asset/Serial ที่ติดตั้งพร้อมตำแหน่งสถานที่และยัง Active
