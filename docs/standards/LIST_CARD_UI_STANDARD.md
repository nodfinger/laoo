# LAOO List and Card Screen Standard

## ข้อกำหนดสำคัญสำหรับหน้าจอใหม่

- ก่อนสร้างหน้าจอใหม่ต้องอ่านมาตรฐาน List/Card และ Pagination รวมถึงมาตรฐาน Action, Popup และ Typography ที่เกี่ยวข้อง
- จัดกลุ่มข้อมูลเป็น Card และจัดระยะห่างให้เรียบร้อยตามมาตรฐาน ตรวจสีทุกจุดตาม User Style และ Semantic Color รวมทั้งชนิด ขนาด และน้ำหนักตัวอักษร; หน้า List/Card ที่มีรายการและรองรับแบ่งหน้าต้องมีปุ่มแบ่งหน้าด้านล่างตามมาตรฐาน
- การเลือกรูปแบบ Action ของหน้าจอใหม่ให้ใช้เกณฑ์จำนวนช่องและการสอบถามตาม `ACTION_UI_STANDARD.md`

มาตรฐานนี้ใช้กับหน้า List/Table และ Card Mode ทุกหน้าจอ โดยต้องอ่าน `UX_UI_STANDARD.md` และ `PAGINATION_UI_STANDARD.md` ร่วมด้วย

ใช้หน้ากลุ่มสิทธิ์ `10003` เป็นภาพอ้างอิงส่วนกลาง โดยจัดหัวข้อและไอคอน Action ชิดซ้ายตามข้อกำหนดด้านล่าง ขนาดทั้งหมดเป็น Flutter logical pixels

## Layout

- สำหรับ `ScreenType = 1` (CRUD) เมื่อเปิด Add/Edit/View ต้องใช้ Action Style ตาม `ACTION_UI_STANDARD.md` เสมอ ไม่ใช้ Layout ของหน้า List/Card แทนหน้า Action

- ใช้พื้นหลังและ Design Token จากส่วนกลางเท่านั้น
- ส่วน Caption, Filter, Table/List และ Pagination เป็น Card สีขาวเต็มความกว้างของ Content Area
- การแสดงข้อมูลแบบ List/Table ทุกหน้าจอต้องอยู่ภายใน Card รายการเสมอ รวมทั้งหัวตาราง แถวข้อมูล และสถานะไม่มีข้อมูล; เว้นระยะจากขอบด้านใน Card ถึงขอบตาราง `10px` ทุกด้าน โดยใช้ `LaooLayout.cardPadding` และไม่นับรวม Padding ภายในเซลล์ตาราง ระยะนี้เป็น Flutter logical pixels
- Card เชิงโครงสร้างของหน้า List ได้แก่ Caption, Filter, Table/List, Pagination, Empty และ Error ต้องกว้างเท่ากันเสมอ โดย Stretch เต็ม Content Area เดียวกันและขอบซ้าย/ขวาต้องตรงกัน; ห้ามใช้ `Center`, `IntrinsicWidth`, `SizedBox(width: ...)` หรือ `maxWidth` กับตัว Card จน Filter Card หดตามจำนวน Control (กำหนดความกว้างได้เฉพาะ TextBox, ComboBox และปุ่มภายใน Card)
- Caption Card, Filter, Table/List และ Pagination แยกเป็น Card คนละ Section และเว้นระยะ `8px` ทุกช่วง
- ใช้เส้น Border จาก User Style ภายในจุดที่มาตรฐานกำหนด ห้ามใช้กรอบสีสร้างขอบซ้ำ
- Pagination Card ต้องวางใต้ Table/List และแสดงเสมอ แม้มีข้อมูลเพียงหน้าเดียวหรือไม่มีข้อมูล โดยใช้รายละเอียดตาม `PAGINATION_UI_STANDARD.md`
- Margin รอบ Content ของหน้า List ใช้ `24px`; จอเล็กให้ลดได้ตามพื้นที่โดยไม่ Overflow
- ข้อยกเว้นหน้า Partner: ระยะขอบ Content ด้านบน ซ้าย และขวาใช้ `LaooLayout.cardMargin` (`10px`) ตามที่พ่อกำหนดเพื่อลดช่องว่าง
- ข้อยกเว้นหน้าข้อมูลด้านเทคนิค: ระยะขอบ Content ใช้ `LaooLayout.cardMargin` (`10px`) ตามที่พ่อกำหนด
- ทุกครั้งที่สร้างหรือแก้หน้า List/Card ต้องตรวจและปรับระยะขอบด้านบน ด้านซ้าย และด้านขวาของ Content ให้ตรงตาม Margin มาตรฐานของหน้าจอนั้นเสมอ รวม Padding จาก Layout ชั้นนอกและ Card ภายใน ไม่ให้ระยะซ้อนกันจนขอบเกินค่าที่กำหนด; ตรวจทั้ง Table Mode, Card Mode และหน้าจอขนาดเล็ก
- Card ทุกตัวไม่มีเส้นกรอบสีและใช้มุมโค้ง `LaooRadius.xs`

## Caption Card

- หน้า List/Card ทุกหน้าจอต้องใช้ Caption Card ตามหน้ากลุ่มสิทธิ์ `10003` เป็นมาตรฐานเดียวกัน ทั้งเมื่อแสดงแบบ List และ Card: ด้านซ้ายเรียง `Icon เมนู → Caption → ดาวเมนูลัด` และด้านขวาเรียง `ปุ่มสลับ List/Card → ปุ่มเพิ่ม` โดยจัดทุกส่วนกึ่งกลางแนวตั้ง ชื่อและ Action ชิดขอบคนละด้าน และไม่ให้ข้อความหรือปุ่มล้นบนหน้าจอเล็ก
- ใช้พื้น Card สีขาวเต็มความกว้าง มุม `4px` ไม่มีเงาและไม่มีกรอบสี; Padding ภายในแนวนอน `16px` แนวตั้ง `14px` และเว้น `8px` จาก Filter Card
- Icon เมนูอยู่ซ้ายสุดของ Caption Card ขนาด `24px` สี Primary จาก User Style ใช้ Icon ตามข้อมูลเมนู และเว้น `8px` ก่อนชื่อหน้าจอ ห้ามกำหนดสีของ Icon ตายตัว
- Caption อ่าน `MenuName` จาก Navigation API/`TDADMainMenu` ห้าม hardcode
- เมื่อเปิดหน้าค้นหาข้อมูลหลักจาก ComboBox ให้ตรวจสิทธิ์ข้อมูลปลายทางจริง: หากไม่มีสิทธิ์เพิ่ม แก้ไข และลบ แต่มีสิทธิ์อ่านข้อมูลที่จำเป็น ให้ใช้ Popup ค้นหาแบบง่ายตาม `POPUP_UI_STANDARD.md` แทนหน้าจัดการ; หากมีสิทธิ์ Action อย่างน้อยหนึ่งอย่าง ให้ใช้หน้าข้อมูลหลักและแสดงหรือปิด Action ตามสิทธิ์จริง โดย API ต้องตรวจสิทธิ์และขอบเขตข้อมูลเสมอ
- Caption ใช้มาตรฐานกลาง `fontSize: 18`, `fontWeight: FontWeight.w700`, `color: Colors.black` ตาม `TYPOGRAPHY_STANDARD.md`
- Icon ดาวอยู่ถัดจาก Caption ใช้สี Primary ของ User Style และต้องกดเพิ่ม/นำออกจากเมนูลัดของผู้ Login ได้
- ดาวโปร่งหมายถึงยังไม่เป็นเมนูลัด กดแล้วเพิ่ม; ดาวทึบหมายถึงเป็นเมนูลัดแล้ว กดอีกครั้งเพื่อนำออก โดยบันทึกผ่านระบบเมนูลัดส่วนกลางในขอบเขตของ User ที่ Login และ MenuCode ของหน้าปัจจุบัน
- เมื่อบันทึกสำเร็จให้อัปเดตสถานะดาวและแถบเมนูลัดทันที; เมื่อบันทึกไม่สำเร็จให้คงสถานะเดิมและแสดงข้อความผิดพลาดที่เข้าใจได้ ห้ามเปลี่ยนเมนูลัดของ User อื่น
- ปุ่ม `+ เพิ่ม` อยู่ขวา ใช้สี Primary มุมโค้ง `4px` และแสดงตาม Permission
- ปุ่ม `เพิ่ม` ใช้ Icon บวกและข้อความสีที่อ่านชัดบนพื้น Primary และซ่อนเมื่อหน้าจอไม่มี Action เพิ่มหรือผู้ใช้ไม่มีสิทธิ์ `CREATE`; ห้ามแสดงปุ่มที่กดเพิ่มได้โดยไม่มีสิทธิ์
- ปุ่ม `เพิ่ม` สูง `LaooTypography.buttonHeight` (`48px`), Padding แนวนอน `16px`, ใช้ Font ปุ่ม `13px`; ความกว้างปรับตามข้อความและ Icon
- ปุ่มสลับ List/Card อยู่ก่อนปุ่มเพิ่ม ห่าง `8px` และมีความสูงเท่าปุ่มเพิ่ม (`48 logical px` ตามค่าปัจจุบัน); ใช้ปุ่มสี่เหลี่ยมจัตุรัส มุม `4px`, Icon `24px` สี Primary และพื้น Primary ความทึบ `10%` โดยหน้าพนักงานเป็นตัวอย่างอ้างอิง
- ปุ่มสลับแสดง Icon รูปตารางสี่ช่องเมื่อกดแล้วจะเปลี่ยนเป็น Card และ Icon รูปรายการเมื่อกดแล้วจะเปลี่ยนเป็น List; เมื่อจอแคบจนบังคับ Card Mode ให้ซ่อนปุ่มสลับตามข้อกำหนด Card Mode
- Caption Card ใช้ Padding แนวนอน `16px` แนวตั้ง `14px`; เว้นระยะ `8px` ถึง Filter Card

## Filter Card

- Filter Card ใช้พื้นสีขาวเต็มความกว้าง ไม่มีเส้นกรอบสี และมุมโค้ง `LaooRadius.xs` (`4px`); Responsive โดยใช้ `Wrap` หรือ Layout ที่ไม่ Overflow
- TextBox ทุกช่องใน Filter Card รวมช่องค้นหา ต้องมี `OutlineInputBorder` เส้น Border จาก User Style และมุมโค้ง `LaooRadius.xs` (`4px`); เมื่อ Focus ใช้เส้นสี Primary ตาม User Style
- Filter Card ใช้ Padding `12px`; ช่องค้นหามี Icon ค้นหาด้านซ้าย และต้องมีปุ่ม `ค้นหา` กับ `ล้าง Filter` แยกเป็นปุ่มสี่เหลี่ยมมุม `4px` ต่อจากช่องค้นหาตามลำดับเสมอ
- ปุ่ม `ค้นหา` เป็น Filled สี Primary พร้อม Icon ค้นหา; ปุ่ม `ล้าง Filter` เป็น Outlined สี Primary พร้อม Icon ล้างตัวกรอง โดยใช้สีจาก User Style และเว้นระยะระหว่างช่อง/ปุ่ม `8px`
- ใช้ความสูงที่แสดงจริงของ TextBox ค้นหาเป็นต้นแบบ โดยคงความสูงของช่องค้นหาเดิม; ปุ่ม `ค้นหา`, `ล้าง Filter` และ ComboBox ในแถว Filter ต้องมีความสูงแสดงจริงเท่าช่องค้นหาและจัดกึ่งกลางแนวตั้งตรงกัน โดยคำนึงถึง Theme, ขนาดตัวอักษร และหน้าจอขนาดเล็ก ห้ามสมมติว่าความสูงช่องค้นหาเท่ากับ `48px` เสมอ
- ปุ่ม `ค้นหา` และ `ล้าง Filter` ใช้ Padding แนวนอน `16px`, Font `13px` และความกว้างปรับตามข้อความและ Icon; หน้าพนักงานเป็นตัวอย่างอ้างอิงขนาดปุ่มที่พ่อมนต์ตรวจแล้ว
- ไม่ Auto Search; ค้นหาเมื่อกด Enter หรือปุ่ม `ค้นหา`; ปุ่ม `ล้าง Filter` ล้างคำค้นและคืนค่าตัวกรองตามค่าเริ่มต้นของหน้าจอ แล้วแสดงข้อมูลตามค่าเริ่มต้น
- ตัวกรองสถานะกว้าง `170px` ในพื้นที่ปกติและวางหลังชุดปุ่มค้นหา/ล้าง Filter; เมื่อพื้นที่ไม่เพียงพอให้ Wrap ลงแถวใหม่โดยคงลำดับและระยะห่าง ไม่ให้ Control ล้น
- ComboBox ใช้ Outline มุม `4px` กรอบปกติสี Border จาก User Style และเมื่อ Focus ใช้ Primary; ตัวกรองอื่นจัดตามพื้นที่โดยไม่ Overflow และคงพฤติกรรมค้นหาของหน้านั้น
- ComboBox ทุกตัวที่ใช้เป็น Filter ต้องมีตัวเลือก `ทั้งหมด` เสมอ การเลือกค่านี้ให้ยกเลิกเงื่อนไขของ Filter ตัวนั้นและแสดงข้อมูลทุกค่าที่ผ่าน Filter อื่น สิทธิ์ผู้ใช้ แพ็กเกจ และขอบเขตบริษัทตามปกติ ห้ามใช้ `ทั้งหมด` เพื่อขยายสิทธิ์หรือข้ามขอบเขตข้อมูล
- ปุ่มทุกปุ่มใช้ Font `13px` และมุมโค้ง `4px`

## Table Mode

- ตารางและคอลัมน์ทั้งหมดต้องอยู่ภายในความกว้าง Content Area ที่มองเห็นเสมอ ห้ามกำหนดความกว้างขั้นต่ำที่ทำให้ตารางกว้างเกินพื้นที่หรือบังคับเลื่อนแนวนอนเพื่อดูคอลัมน์; จัดสัดส่วนคอลัมน์ตามพื้นที่และตัดข้อความด้วย ellipsis เมื่อจำเป็น โดยต้องคงข้อมูลครบถ้วนไว้ในระบบ
- เมื่อพื้นที่ไม่พอให้แสดงทุกคอลัมน์และปุ่ม Action ได้โดยไม่ล้น ให้เปลี่ยนเป็น Card Mode อัตโนมัติ โดยให้ผู้ใช้ยังเข้าถึงข้อมูลและ Action ได้ครบ
- ไม่มีกรอบสีรอบนอก
- หัวตารางสูง `56px` ใช้พื้น Primary ความทึบ `12%`; ข้อความหัวตารางใช้ Primary ขนาด `14px` น้ำหนัก `700`; แถวข้อมูลสูง `48–56px`
- ข้อความข้อมูลใช้ `14px` และสีข้อความตาม Theme ของ User ที่ Login
- ข้อมูลสถานะทั้งใน Table และ Card ต้องแสดงเป็นป้ายมีพื้นสีอ่อน มุม `999px` และ Padding แนวนอน `10px` แนวตั้ง `4px`; สถานะปกติหรือสถานะทั่วไปใช้สี Primary ของ User Style กับพื้นสีเดียวกันที่ความทึบ `12%`; สถานะไม่ปกติ ไม่ใช้งาน หรือยกเลิกใช้สี Semantic Error/Delete กับพื้นสีเดียวกันที่ความทึบ `12%` โดยห้ามกำหนดสีประจำ User ตายตัว
- เส้นคั่นระหว่างหัวตารางและใต้ทุกแถวข้อมูล รวมแถวสุดท้าย เป็นเส้นแนวนอนหนา `0.6px` ใช้ Semantic Border Color จาก User Style ที่ Login ห้ามกำหนดสีคงที่รายตารางหรือใน Widget กลาง และต้องเปลี่ยนตาม User Style
- ไม่มีเส้นแนวตั้งหรือกรอบรอบนอก; ระยะขอบตารางแนวนอน `8px` และระหว่างคอลัมน์ `20px`; ตารางที่ตรึงหัวและเลื่อนเนื้อหาต้องแสดงเส้นคั่นด้วยสีและความหนาเดียวกัน
- คอลัมน์แรกเป็น `ID` เรียงตามลำดับรายการ และคอลัมน์ที่สองเป็น `Action`
- Caption `Action` และไอคอน Action ทุกแถวต้องชิดซ้ายภายในคอลัมน์เดียวกันและมีแนวเริ่มต้นตรงกัน; ไอคอนแก้ไขใช้ Primary และไอคอนลบใช้สี Error/Delete ตามสิทธิ์
- ทุกคอลัมน์ใน List ที่แสดง Icon หรือปุ่มกด เช่น `รูป` ต้องจัด Caption และ Icon หรือปุ่มแต่ละแถวชิดซ้าย โดยให้แนวเริ่มต้นของรูปตรงกับ Caption และรักษาพื้นที่กดให้ใช้งานได้สะดวก
- หากรหัสรายการถูกสร้างโดยระบบอัตโนมัติ ห้ามแสดงรหัสดังกล่าวเป็นคอลัมน์หรือข้อความใน Table/List และ Card Mode ทุกหน้าจอ เช่น ไม่แสดง `รหัสกลุ่มสิทธิ์` ที่ระบบสร้าง `00001`; กติกานี้ใช้กับรหัสที่สร้างอัตโนมัติ ไม่ว่าชื่อ Field จะเป็น Code หรือ ID
- `ID` ในคอลัมน์แรกตามมาตรฐานนี้หมายถึงเลขลำดับแถวที่แสดงในรายการเท่านั้น ไม่ใช่ Primary Key หรือรหัสอัตโนมัติของข้อมูล; ยังคงแสดงเลขลำดับและ `Action` ตามเดิม
- การซ่อนเป็นข้อกำหนดด้านการแสดงผลเท่านั้น ต้องเก็บรหัสและ Primary Key ที่จำเป็นไว้สำหรับอ้างอิงรายการ, การแก้ไข, การลบ, Permission และ API ตามเดิม ไม่ลบข้อมูลหรือเปลี่ยน Business Logic
- รหัสที่ผู้ใช้กำหนดเองไม่อยู่ในข้อห้ามนี้ และยังแสดงได้ตามข้อกำหนดของหน้าจอนั้น
- Edit ใช้ Primary, Delete ใช้สี Error/Delete และแสดงตาม Permission โดยจัดชิดซ้ายตามแนว Caption `Action`
- รองรับ Sort เฉพาะคอลัมน์ที่ระบบกำหนดไว้เดิม

## Card Mode

- ใช้หน้ากลุ่มสิทธิ์ `10003` ในภาพ Card Mode เป็น Visual Reference: Caption Card, Filter Card, รายการ Card และ Pagination แยกส่วนและเรียงตามลำดับ โดยขอบซ้าย/ขวาตรงกันเต็ม Content Area
- แถบ Caption มีปุ่มสลับมุมมองและปุ่ม `เพิ่ม` ด้านขวาตาม Permission; แถบ Filter ใช้ช่องค้นหาและตัวกรองตามหัวข้อ Filter Card; Pagination ใช้มาตรฐาน `PAGINATION_UI_STANDARD.md`
- เมื่อพื้นที่ตารางแคบกว่า `600px` ให้เปลี่ยนเป็น Card Mode อัตโนมัติ และอาจเปลี่ยนที่ความกว้างมากกว่านั้นได้เมื่อคอลัมน์ไม่พอ โดยไม่เลื่อนตารางแนวนอน
- Card แต่ละรายการใช้พื้นสีขาว ไม่มีเงา ไม่มีเส้นกรอบสี มุม `4px` และกว้างเต็มพื้นที่รายการ; Padding ซ้าย `14px` บน `10px` ขวา `8px` ล่าง `10px`
- ชื่อหลักของรายการอยู่ด้านซ้าย ใช้สี Primary ตาม User Style และน้ำหนัก `w700`; ขนาดตัวอักษรและ Font ใช้ Theme/`LaooTypography` กลาง ห้ามกำหนดสี Primary ตายตัว
- ด้านขวาเรียงป้ายสถานะ ตามด้วยไอคอนแก้ไขและลบตามสิทธิ์; ป้ายสถานะใช้มุม `999px`, Padding แนวนอน `10px` แนวตั้ง `4px`, ข้อความน้ำหนัก `w700` และพื้นสีสถานะความทึบ `12%`
- สถานะเปิดและไอคอนแก้ไขใช้ Primary ของ User Style; สถานะปิดและไอคอนลบใช้ Semantic Error/Delete ตาม Theme; หากหน้าจอไม่มีสถานะหรือ Action ใดให้ละส่วนที่ไม่เกี่ยวข้อง
- ข้อมูลและ Action ต้องไม่ Overflow; เมื่อพื้นที่แคบสามารถ Wrap หรือจัดหลายแถวได้โดยคงลำดับและสิทธิ์การใช้งาน
- เมื่อ List หรือ Card แสดงภาพจริง ผู้ใช้ต้องกดภาพเพื่อเปิดดูภาพเต็มและซูมได้ โดยจำกัดพื้นที่ Popup ตามหน้าจอและตรวจสิทธิ์การเข้าถึงภาพตามเดิม; ภาพแทนเมื่อไม่มีรูปไม่ต้องเปิด Popup
- ระยะห่างระหว่าง Card แต่ละรายการ `8px` พอดี
- ให้ใช้ `ListView.separated`, `GridView` หรือ Layout ที่ได้ระยะเท่ากัน และตั้ง `Card.margin` เป็นศูนย์เมื่อจำเป็น
- ห้ามพึ่ง `Card` default margin เพราะจะทำให้ระยะจริงคลาดเคลื่อน
- ถ้าหน้าจอแคบจนบังคับ Card Mode ต้องซ่อนปุ่มสลับ List/Card; ปุ่มสลับแสดงเฉพาะหน้าจอกว้างปกติ
