# PAGINATION_UI_STANDARD

## 1. วัตถุประสงค์

เอกสารนี้กำหนดมาตรฐาน UI/UX สำหรับปุ่มแบ่งหน้าข้อมูล (Pagination) ของ Laoo
Solutions เพื่อให้หน้าจอ List/Table ทุก Module ใช้งานรูปแบบเดียวกัน

มาตรฐานนี้เริ่มต้นจากรูปแบบที่กำหนดร่วมกันในหน้า Partner List
และใช้เป็นแนวทางกลางสำหรับหน้ารายการข้อมูลอื่นต่อไป

## 2. รูปแบบหลัก

Pagination ต้องแสดงเลขหน้าแยกเป็นปุ่ม เช่น:

**ก่อนหน้า 1 2 3 4 5 ถัดไป**

ห้ามใช้เพียงข้อความรูปแบบ `หน้า 1 / 5` เป็นตัวควบคุมหลัก
เมื่อระบบสามารถแสดงเลขหน้าให้ผู้ใช้เลือกโดยตรงได้

## 3. ตำแหน่ง

-   Pagination อยู่ด้านล่างของ Table/List
-   Pagination จัดชิดซ้ายของพื้นที่ Table/List
-   Table/List จัดชิดซ้ายเสมอ
-   ตำแหน่ง Pagination ต้องอ้างอิงพื้นที่ของ Table/List ไม่ใช่ตำแหน่งกึ่งกลางของหน้าจอ
-   เมื่อหน้าจอ Responsive ตำแหน่งต้องยังคงสัมพันธ์กับพื้นที่ List

## 4. ปุ่มเลขหน้า

-   แต่ละเลขหน้าเป็นปุ่มแยกจากกัน
-   ผู้ใช้สามารถกดเลขหน้าเพื่อไปยังหน้านั้นได้โดยตรง
-   หน้าปัจจุบันต้องมองเห็นได้ชัดเจน
-   หน้าปัจจุบันใช้สี Primary ของ Theme/STYLE ที่ผู้ใช้เลือก
-   เลขหน้าที่ไม่ได้เลือกใช้รูปแบบ Outline
-   สีของ Pagination ห้าม Fix เป็นสีเฉพาะ Module แต่ต้องเปลี่ยนตาม Theme/STYLE

## 5. ปุ่มก่อนหน้าและถัดไป

Pagination ต้องมี:

-   `ก่อนหน้า`
-   `ถัดไป`

พฤติกรรม:

-   หน้าแรก: ปุ่ม `ก่อนหน้า` ต้องกดไม่ได้
-   หน้าสุดท้าย: ปุ่ม `ถัดไป` ต้องกดไม่ได้
-   หน้าอื่น: ปุ่มทำงานตามปกติ
-   ปุ่มใช้ Button Style เดียวกับระบบ ไม่ใช้ข้อความธรรมดาที่ไม่มีสถานะปุ่ม

## 6. กรณีมีจำนวนหน้ามาก

หากจำนวนหน้าไม่มาก สามารถแสดงเลขหน้าทั้งหมดได้ เช่น:

`ก่อนหน้า  1  2  3  4  5  ถัดไป`

หากมีจำนวนหน้ามาก ให้ย่อช่วงด้วย `...` เพื่อไม่ให้ Pagination กว้างเกินไป เช่น:

`ก่อนหน้า  1  ...  5  6  7  8  9  ...  20  ถัดไป`

ระบบควรแสดงเลขหน้าบริเวณใกล้หน้าปัจจุบัน และเปิดทางให้เข้าหน้าแรก/หน้าสุดท้ายได้ง่าย

## 7. ความสัมพันธ์กับ RowSTD

จำนวนข้อมูลต่อหน้าต้องใช้ค่ามาตรฐาน `RowSTD` ที่ระบบกำหนด

หลักการ:

-   Pagination ต้องคำนวณจำนวนหน้าจากจำนวนข้อมูลและ RowSTD
-   การเปลี่ยน RowSTD ต้องทำให้จำนวนหน้าและข้อมูลในแต่ละหน้าปรับตาม
-   ห้ามกำหนดจำนวนแถวต่อหน้าแบบ Hard-code ในแต่ละ Module หากมีค่ากลาง RowSTD
    ให้ใช้งานแล้ว

## 8. ข้อมูลประกอบ Pagination

สามารถแสดงข้อความจำนวนรายการต่อท้าย Pagination เช่น:

`แสดง 1-10 จาก 35 รายการ (หน้าละ 10)`

ข้อความนี้เป็นข้อมูลประกอบ ไม่ใช่ตัวควบคุมการเปลี่ยนหน้า

## 9. Responsive

บน Desktop/Tablet ที่มีพื้นที่เพียงพอ:

-   แสดง `ก่อนหน้า`
-   แสดงเลขหน้า
-   แสดง `ถัดไป`
-   แสดงจำนวนรายการประกอบได้

เมื่อพื้นที่แคบ:

-   Pagination สามารถ Wrap ลงบรรทัดใหม่ได้
-   ต้องไม่ทำให้ Table/List ถูกจัดกึ่งกลางโดยไม่ตั้งใจ
-   ปุ่มต้องยังสามารถกดได้สะดวก
-   ต้องรักษาหน้าปัจจุบันและลำดับเลขหน้าให้เข้าใจง่าย

## 10. Theme Standard

Pagination ต้องรองรับ Theme/STYLE ของ Laoo Solutions

-   Active Page = Primary Color
-   Outline/Focus = อิง Theme
-   Text/Icon = ต้องมี Contrast ที่อ่านได้ตามพื้นหลัง
-   ห้าม Fix สีที่ทำให้ White/Dark/Hybrid Theme แสดงผลผิด
-   เมื่อผู้ใช้เปลี่ยน STYLE Pagination ต้องเปลี่ยนสีตามทันที

## 11. ขอบเขตการใช้งาน

มาตรฐานนี้ใช้กับหน้าจอประเภท:

-   Master Data List
-   Setup List
-   Transaction List
-   Search Result List
-   Table/List ที่มีข้อมูลมากกว่าหนึ่งหน้า

ตัวอย่างเริ่มต้น: Partner List

## 12. ข้อกำหนดสำหรับการพัฒนา

เมื่อสร้าง Pagination ใหม่:

1.  ใช้ RowSTD เป็นจำนวนรายการต่อหน้า
2.  Table/List ชิดซ้าย
3.  Pagination อยู่ด้านล่างและชิดซ้ายของพื้นที่ List
4.  ใช้ปุ่มเลขหน้าแบบเลือกโดยตรง
5.  Active Page ต้องตาม Primary Theme
6.  มี Previous/Next และ Disabled State ที่ถูกต้อง
7.  รองรับ `...` เมื่อมีหลายหน้า
8.  รองรับ Responsive
9.  ห้ามกระทบ Business Logic ของ List
10. ห้ามกำหนดสีที่ขัดกับ Theme/STYLE
