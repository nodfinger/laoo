# Document Control: draft flow audit

Baseline: `6a86a42`. This is a source review, not an integration test.

| Requirement | Finding | Status |
| --- | --- | --- |
| DC-01 | Company-scoped document number uniqueness exists. Draft form now supplies the owning department and API checks that it belongs to the company. | Partial; integration tests pending |
| DC-02 | A separate draft revision can be created and edited with an explicit `BasedOnRevisionID`; the effective document and `CurrentRevisionID` are not changed. Creation is serialized and refuses another pending revision. The owner can attach a primary PDF to that draft. Submission/publishing are not yet connected to this new flow; no API/UI integration test has been run. | Partial |
| DC-03 | Menu and company checks exist; draft mutations now require the owner, and detail/file access is restricted to the owner, assigned reviewers/approvers or the authorized audience of the effective revision. List results are filtered by owner, assignee or published audience. Validate these owner-only rules with business owners; branch scope and end-to-end tests are still pending. | Partial |
| DC-04, DC-05 | New document and revision drafts create a change-request record. Drafts support multiple related document numbers after company, menu and audience checks, and capture their revisions. An owner may save a withdrawal request draft without changing the effective document. Existing legacy drafts are not backfilled; the withdrawal approval lifecycle is not implemented. | Partial; API/UI integration tests pending |
| DC-10 | Upload stores a checksum and links a file to a revision. Saving a draft and uploading the file are separate requests; failures are now reported and the draft can be reopened to retry. | Partial; no atomic save and upload |
| DC-15 | Create/edit/upload insert audit records. Draft deletion now marks the document inactive and records DELETE without deleting files, revisions or earlier audit entries; its document number remains reserved. Broader append-only protections have not been established. | Partial; integration tests pending |
| DC-18 | Existing status labels migration preserves status codes. No data migration was introduced for general draft behavior. | Unverified beyond status migration test |

New general documents are saved as drafts. Existing published documents are not converted. Existing published general documents are protected from edit, replacement upload and deletion. New revision drafts support the revision number, change summary, reason, impact assessment, related documents and a primary PDF; promotion is not implemented. Saving a returned document resets both the document and its revision to draft. Publishing a new general draft is not implemented as part of this change and must be delivered before those drafts are used in production. Migrations `20261118110000_LAOO_DOCUMENT_revision_based_on`, `20261118130000_LAOO_DOCUMENT_revision_change_context` and `20261118140000_LAOO_DOCUMENT_draft_change_requests` have been tested in a separate test database only. Migration `20261118150000_LAOO_DOCUMENT_withdrawal_request_drafts` is not yet tested: the automatic approval review could not refresh the authentication token. All migrations must be tested and deployed in order before the changed API. A transaction-scoped SQL schema check confirmed a draft revision can refer to a current effective revision without changing the document's current pointer; this is not an API or concurrency test.
