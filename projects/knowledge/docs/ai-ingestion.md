# KM: เตรียมแหล่งความรู้สำหรับ AI

- `AI_TEXT` และ `AI_IMAGES` ไม่แสดงในคลังความรู้ทั่วไป ผู้มีสิทธิ์จัดการและตรวจทานยังเห็นข้อมูลตามหน้าที่
- เมนูจัดการองค์ความรู้ `49003`: ผู้มีสิทธิ์ `CREATE` ใช้สิทธิ์อ่าน OCR และอัปโหลดไฟล์ได้; ผู้มี `UPLOAD` เดิมยังอัปโหลดได้ โดยการอ่าน OCR สำหรับผู้ไม่มี `CREATE` ต้องมี `EDIT` ด้วย ตรวจ Company และแพ็กเกจจากสิทธิ์กลางทุกครั้ง
- ตั้งค่า `IncludeInAi` แยกตาม Revision ค่าเริ่มต้นเป็น `false` และคัดลอกจากฉบับเผยแพร่เมื่อสร้างฉบับแก้ไข
- รูปอ่านด้วย Tesseract ภาษาไทยและอังกฤษในเครื่อง ส่วน PDF ใช้ Python แบบออฟไลน์และ PDFium แยกข้อความทีละหน้า หน้าที่ไม่มีข้อความเพียงพอใช้ OCR จาก Tesseract ต้องตรวจข้อความก่อนส่งตรวจทาน
- สำหรับ PDF รองรับไม่เกิน 100 หน้าและไม่เกิน 20 MiB หรือตามขนาดไฟล์แนบของบริษัทหากน้อยกว่า อ่านทีละหน้าเพื่อให้สอดคล้องกับเวลารอของ Core API
- `Knowledge:PythonPath` กำหนด Python ที่มี `pypdfium2` และ `Pillow`; ค่าตั้งต้นคือ `tools/ocr-python-portable/python.exe` ที่อยู่ข้างโฟลเดอร์ `laoo_api` ของ content root API. `Knowledge:TesseractPath` กำหนด tesseract.exe; ค่าตั้งต้นคือ `Program Files/Tesseract-OCR/tesseract.exe`. `Ocr:TessdataPath` กำหนดโฟลเดอร์โมเดลภาษา ค่าเริ่มต้นคือ `laoo_api/App_Data/tessdata`
- API `GET /api/company/knowledge/ai/sources?query=...` เป็นจุดอ่านแหล่งความรู้แบบค้นคำที่ต้องมีสิทธิ์เมนู `49005` และผ่านเงื่อนไข Company/Audience โดยใช้เฉพาะ Revision ที่เผยแพร่และเลือกใช้ AI แล้ว ไม่รวมข้อมูลเก็บถาวรและข้อมูลที่กำลังมีฉบับแก้ไข เนื่องจาก Audience ยังไม่ได้แยกตาม Revision
- API แหล่งความรู้เป็นการค้นแบบคำ ไม่ใช่ semantic search หรือระบบตอบคำถาม RAG; การเชื่อม AI กลาง การสร้างดัชนี semantic การอ้างอิงถึงหน้าต้นทาง และการตอบพร้อมสิทธิ์ต้องทำต่อใน Core แยกจาก Project KM
