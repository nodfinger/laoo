# การเชื่อมสิทธิ์ผู้ตรวจทานองค์ความรู้

การกำหนดผู้ตรวจทานใช้ทะเบียนสิทธิ์ระดับย่อยกลาง ไม่สร้างทะเบียนพนักงานแยกใน KM

## สิทธิ์ระดับย่อยกลาง

- ตรวจพบว่า Core เปิดการแสดงสิทธิ์ระดับย่อยของเมนู `49003` และลงทะเบียนรหัส `REVIEW_KNOWLEDGE` แล้วในฐานข้อมูลที่เชื่อมอยู่
- ณ การตรวจ `origin/main` ยังไม่พบรหัส `REVIEW_KNOWLEDGE` ใน source/migration กลาง จึงต้องให้ Core ตรวจการนำทะเบียนนี้ขึ้น GitHub ก่อนติดตั้งในฐานข้อมูลอื่น
- ใช้หน้ากำหนดสิทธิ์ระดับย่อยกลางเลือกพนักงาน ซึ่งรองรับการกรองตามแผนกและค้นรหัส ชื่อ หรือชื่อเล่น
- KM ใช้ ProjectID ตามบริบทผู้เข้าสู่ระบบเช่นเดียวกับ `CompanySubPermissionController.Current` และ `SaveEmployees` ปัจจุบัน; Company Admin ได้สิทธิ์ย่อยทั้งหมดตามสัญญา Core เดิม
- ไม่ให้สิทธิ์พนักงานโดยอัตโนมัติ; ผู้ตรวจต้องมีสิทธิ์เมนูและ Action กลางที่เกี่ยวข้องด้วย

## เงื่อนไขของ KM

- กำหนดขอบเขตผู้ตรวจแยกตามประเภท: แผนกเดียวกับผู้จัดทำ, ฝ่ายเดียวกับผู้จัดทำ หรือไม่จำกัดฝ่าย/แผนก
- ผู้ตรวจต้องได้รับสิทธิ์ย่อยที่กำหนด และผ่านสิทธิ์เมนูกับ Action ของระบบเดิมด้วย ตรวจซ้ำทั้งการแสดงรายการ อ่านรายละเอียด เผยแพร่ และส่งกลับ
- อ่านผู้จัดทำจากรายการนั้นและพนักงานของผู้เข้าสู่ระบบภายในบริษัทเดียวกัน; หากไม่พบสังกัดที่ต้องเทียบ ให้ไม่ผ่านเงื่อนไข ไม่ถือว่าเป็นสังกัดเดียวกัน
- การเผยแพร่ทันทีใช้ได้เมื่อประเภทอนุญาต ไม่ส่งข้อมูลให้ AI และไม่ขัดข้อกำหนดอนุมัติกลาง; รายการส่งให้ AI ต้องผ่านตรวจทาน
- ใช้สิทธิ์และสังกัดปัจจุบันเสมอ แม้รายการส่งตรวจไปแล้ว: ตรวจใหม่ทุกครั้งเมื่อแสดงรายการ เปิดรายละเอียด เผยแพร่ หรือส่งกลับ ไม่ยึดข้อมูล ณ วันที่ส่งตรวจ
- ทดสอบกรณีย้ายฝ่ายหรือแผนก ข้ามบริษัท สิทธิ์ถูกถอน และไม่มีผู้ตรวจที่มีสิทธิ์ก่อนเปิดใช้
