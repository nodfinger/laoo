# ตรวจสอบข้อมูล PMS และ SAP

- เมนู `65002`, ScreenType `3`, route `mySystemSapPms`; ชื่อเมนูและสิทธิ์ `VIEW` มาจากระบบกลาง
- ผู้ใช้เลือกไฟล์ `.xlsx` สองไฟล์ ข้อมูลถูกอ่านและเปรียบเทียบในหน่วยความจำฝั่งเว็บ โดยไม่ส่งเนื้อหาไฟล์ไป API หรือเก็บลงฐานข้อมูล
- ชื่อไฟล์ที่เลือกในช่อง PMS ต้องมีคำว่า `pms` และช่อง SAP ต้องมีคำว่า `sap` โดยไม่แยกตัวพิมพ์เล็กและใหญ่
- เมื่อเปรียบเทียบ ระบบบันทึกข้อมูลสรุปใน `dbo.TDPSComparisonHistory`: ชื่อไฟล์ จำนวนรายการ ช่วงวันที่ ผู้ทดสอบ เวลา จำนวนผลแต่ละสถานะ และเลขที่เอกสารที่พบปัญหา โดยไม่เก็บไฟล์หรือข้อมูลทั้งหมดในไฟล์
- `POST /api/sap-pms/history` บันทึกสรุปจากหน้าจอ และ `GET /api/sap-pms/history` แสดงประวัติตามบริษัทและสิทธิ์ `VIEW` รวมถึงขอบเขตข้อมูลเมื่อเปิดใช้งาน สรุปนี้เป็นข้อมูลที่หน้าจอส่งมา ไม่ใช่การตรวจไฟล์ซ้ำโดยเซิร์ฟเวอร์
- อ่านเลขที่เอกสาร วันที่เอกสารหรือวันที่สร้างเอกสาร และ `PmsStatus` จากหัวคอลัมน์ PMS; คอลัมน์เลขที่เอกสารของ SAP อยู่ตำแหน่งเดียวกับ PMS และจับคู่ตามเลขที่เอกสาร
- เปรียบเทียบคอลัมน์ตามตำแหน่ง PMS; ข้ามคอลัมน์ที่ไม่มีหัวคอลัมน์ใน SAP; รายการ `PmsStatus=2` ต้องพบใน SAP และมีข้อมูลตรงกัน สถานะอื่นแสดงว่ายังไม่ส่ง
- เลขที่ซ้ำ ข้อมูลบังคับผิดหรือไม่ครบ ไม่พบคู่ และค่าที่ต่างกันแสดงเป็นปัญหา; รายการ SAP ที่ไม่มี PMS แสดงรวมโดยไม่ใช้ช่วงวันที่ PMS
- ส่งออกเฉพาะผลที่กรองในหน้าจอเป็น `.xlsx` เมื่อเมนูอนุญาตและผู้ใช้มีสิทธิ์ `EXPORT`; `GET /api/sap-pms/permissions` ตรวจ `VIEW`, `AllowExport` และ `EXPORT` จากระบบกลาง โดยไม่รับข้อมูลไฟล์
- เมนูเปิดการส่งออกด้วย core migration `20261115140000_LAOO_sap_pms_export.sql`; migration เปลี่ยนเฉพาะ metadata ของเมนู ไม่กำหนดสิทธิ์ให้ผู้ใช้และไม่สร้างตารางเก็บข้อมูล
